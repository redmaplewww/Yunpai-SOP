# SOP 工艺路线知识库设计规格（2026-08-11）

## 验收目标

1. 工艺路线在排版前形成可变步骤、父子层级和逐字段来源的中间模型。
2. 只有人工批准的不可变版本可被后续产品自动复用；演示批准与正式生产批准严格隔离。
3. 未知项必须说明原因、责任角色和所需证据。
4. 审核员可以在本地 Web 工作台增删拆并排步骤并逐字段确认。
5. 渲染器不改变路线；本轮不自动填图。
6. 产品身份、BOM、设备治具、参数、QC、包装标签、IE与发布签核必须作为八个独立、版本化的route section审核。
7. 正式生产批准必须通过逐步、逐section、blocking unknown、冲突/占位符/型号和产品专属token闸门；失败不得产生批准快照或正式索引副作用。

## 决策

- 使用独立 SQLite，不复用制造主业务数据库。
- Pydantic 定义进程边界 schema，SQLite 约束和 trigger 守住持久化边界。
- 路线复用以 exact/alias/family/features/FTS 为检索面，以 `reuse_link` 和 `field_provenance` 记录来源。
- 旧两页交接包仅保留为可选 render adapter，不作为路线真源。
- 当前两个真实产品输出保持 DRAFT，禁止冒充生产批准。
- demonstration_only 按钮与正式批准分离并显示风险；两个真实产品不会由构建脚本自动确认或批准。

## 非目标

- 不自动批准或发布 SOP。
- 不推断设备型号、工装编号、工时、抽样频次和现场合格窗口。
- 不在只读资料目录写入任何文件。
